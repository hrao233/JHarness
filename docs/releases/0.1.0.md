# JHarness 0.1.0

This local Windows development build includes:

- Electron/React desktop and shared-runtime CLI entry;
- durable tasks, approvals, recovery and task-center control;
- task reports, plans, command evidence, acceptance criteria and artifacts;
- conflict-aware file checkpoints, whole-run restore and isolated Git worktrees;
- optional process-isolated tool plugins and Edge/Chrome DevTools integration;
- scheduled local tasks while the desktop application is open;
- verified local-data backup, integrity inspection and guarded restore.

The build requires Windows x64 and ships its own Java runtime. Model credentials are supplied by the
user in desktop settings or by `JHARNESS_API_KEY` for the CLI. The packaged `release-manifest.json`
records the build version, Git commit and workspace state when packaged, and the size and SHA-256
digest of each bundled file. From the source checkout, run `npm run verify:release` for a local
build, or `npm run verify:release -- <extracted-directory>` for a downloaded bundle.

Successful [Windows workflow runs](../../.github/workflows/verify-windows.yml) retain the portable
bundle for 14 days. The bundle can be downloaded from the run's
[Artifacts section](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts).

This is an unsigned portable development build. Create a backup from the data maintenance panel
and close JHarness before replacing a previous bundle. Extract the new bundle into a separate
directory and launch `JHarness.exe`; it uses the existing desktop data directory. Keep the previous
bundle and backup until the new build can reopen your projects and sessions.
The upgrade path from a previously distributed version has not yet been validated.
