# JHarness 产品成熟度路线图

更新于 2026-11-16

JHarness 的目标是成为可以日常使用的开发助手。用户打开一个真实仓库，可以从理解需求、规划、修改和验证一路走到交付，随时看清工具做了什么、改了哪些文件、为什么停下。重启后能继续未完成的工作，升级后还能读取已有项目数据，需要新能力时可以扩展运行时。

[Hermes 与 Pi 功能盘点](../research/hermes-pi-capabilities.md)列出两套应用、库和原型实际实现的能力，[AgentScope Lite 架构](../architecture/agentscope-lite.md)定义模块边界。原 Phase 0–6 记录本地运行时迁移。本路线图覆盖迁移之后的产品演进。

## 当前进度

| 阶段 | 用户可以做到什么 | 当前状态 |
| --- | --- | --- |
| M1 · 可用的本地助手 | 在 Windows 打开项目、对话、审批工具、使用记忆和 Skill、重开历史会话 | 本地主流程已验证；Windows CI 配置已修复，待干净运行器验证 |
| M2 · 可恢复的任务 | 关闭或重启应用后查看未完成任务，从可恢复的位置继续 | 待审批任务已纳入打包恢复冒烟；任务排队、补充指令、结果核对和继续均已贯通。剩余“已批准执行中/结果未知”的打包故障注入 |
| M3 · 可追溯的会话与上下文 | 查阅、导出、分叉会话，查看哪些内容进入了模型上下文 | 分叉、上下文检查、Markdown/JSON 导出、长会话预算、v1 迁移和中文/英文检索样本已接入；完整迁移集与召回质量语料待补 |
| M4 · 可交付的项目工作流 | 从需求到改动与验证结果，能审阅产出并追溯执行过程 | 已有工具、待办和审批；计划、执行和验证的桌面联动待交付 |
| M5 · 可扩展的桌面与 SDK | 安装、启停和升级外部能力；开发者能用公开 API 构建扩展 | 已有库级注册器和进程宿主；桌面接入和能力级 RPC 待交付 |
| M6 · 可持续发布与升级 | 获取可追溯的 Windows 构建，升级时保留数据，故障后能恢复和诊断 | 已有本地打包、冒烟和预算测试；发布及升级链路待交付 |
| M7 · 多入口与可选集成 | 通过其他入口使用同一运行时，按项目需要接入外部能力 | 已有网关等库层基础，待选择场景并交付 |
| M8 · 后台自动化与任务编排 | 创建、暂停和重跑定时或事件任务，追踪依赖、审批、运行历史和结果 | 库内有任务基础，待实现产品调度与管理 |
| M9 · 多项目配置与运维 | 在多个项目和配置档案之间切换，管理模型、工具、数据与运行状态 | 已有按项目组织的数据和模型设置，待补齐管理与恢复链路 |

这些阶段描述可用能力，代码可以交错交付。例如 M2 的桌面任务接入、M5 的外部消费者样例与 M6 的 Windows CI 修复可以并行。阶段完成以实际入口的可重复演示和验证为依据。桌面功能要从桌面操作验证，SDK 功能要从独立调用方验证。每次交付更新上表与 [进度记录](../progress/agentscope-lite.md)，标明新打通的入口、对应验证和剩余差距。

## 交付节奏与规模

JHarness 的长期目标是一个大规模、可持续维护的桌面开发工具。代码规模是结果，不是验收标准；不能为了接近 10 万行目标填写重复抽象、空实现或只存在于计划里的模块。

后续每次实质推进按纵向能力交付，默认同时覆盖：

- 领域状态和持久化语义；
- 后端协议与执行路径；
- 桌面入口和用户可见状态；
- 跨进程或故障恢复测试；
- 文档、已知差距和下一步依赖。

一个里程碑通常跨多个模块，不能只增加几百行孤立代码。若一个需求可以拆成独立可验收的能力，应一次完成至少一条端到端链路，再继续扩展。每个阶段仍以真实入口、可重复验证和剩余差距为准。

## M1 · 可用的本地助手

保留已有会话、项目文件操作、审批、记忆、Skill 和模型设置。继续使用仓库内构建的 Java 运行时模块和 Windows 桌面包。

**验收场景**　在 Windows 打开打包后的应用，连接本地模拟模型，打开项目、获得流式回复、审核一次文件修改，再关闭应用并重开会话。现有 Node 端到端测试和打包首页冒烟已分别验证了后端主流程与桌面渲染。把这两部分连成打包应用内的完整场景，纳入 M6 的验证。

## M2 · 可恢复的任务

- 已把桌面聊天接到 `AgentSession` 的任务提交、状态订阅、取消和恢复。任务中心可列出跨会话的排队、运行、等待审批和中断任务，并回到对应会话。
- 已区分运行中补充指令与排队的后续请求，任务卡会展示待审批项和可继续条件。
- 已持久记录已确认的工具结果。崩溃后遇到结果未知的写入或命令时，任务卡会列出具体工具调用，用户逐项确认“已完成”或“未执行”后继续。恢复时复用已有任务和已确认的结果。

**验收场景**　在打包桌面提交一个包含写入和审批的任务，分别在等待审批、工具结果已确认和执行结果未知时终止进程。重开后能找到同一个任务，按状态继续或取消。重复提交同一个请求只产生一个任务，已完成的写入不会因重启再执行一次。运行中补充指令和后续任务按各自的顺序执行。

## M3 · 可追溯的会话与上下文

- 已将会话历史、最近模型可见上下文和项目记忆拆成独立视图。用户能查看最近请求的模型、消息、工具、上下文项、检查点和压缩状态，并导出 Markdown 全文或原始事件 JSON。
- 区分项目事实、个人偏好和运行证据。长会话评估覆盖中文与英文召回，查看结果能定位到原始消息。为上下文压缩、缓存使用和历史检索保留可比较的指标。
- 已支持从明确的消息创建会话分支，并记录来源。分叉使用干净状态基线，不复制未结束的 run；后续模型请求可继续，原始对话和工具记录继续可查。
- 已有 v1 会话事件样本，并增加 1,200 条消息的合成长会话检查/导出预算测试。代表性迁移全集、中文和英文召回质量样本仍需补齐；根据实际查询耗时决定是否引入可重建索引。

**验收场景**　打开旧版数据，进行一次压缩，在指定检查点派生新会话。原会话的消息 ID、历史和搜索结果保持一致，新会话可跳转到来源，重启后两边均可打开。固定样本能重建当时的上下文选择和来源。

## M4 · 可交付的项目工作流

- 把计划、变更和验证接到同一个任务。桌面能查看阶段、工具运行记录、文件差异、测试结果和遗留事项；用户可以调整计划、暂停或取消。
- 复用项目记忆、版本控制视图和命令工具。把测试失败、跳过和缺少验证条件显示在任务结果中，保留退出码和可定位的证据。
- 为跨文件任务提供可选工作树或等价隔离工作区，展示文件检查点、预览差异和按文件恢复。检查点保留用户后来手改的内容。任务记录能打开日志、报告等交付物。
- 在项目内接入可选的子任务或子代理，先支持并行阅读和验证。父任务能看到结果、停止子任务，并对写入和命令使用同一套项目权限与审批规则。

**验收场景**　在真实项目样本中选择一个跨文件改动。用户能审阅计划、批准变更、核对已执行的测试并打开交付物。恢复一个改动文件时，保留用户随后在另一个文件中的编辑。取消父任务能结束它仍在运行的子任务。

## M5 · 可扩展的桌面与 SDK

- 在正常桌面启动路径接入插件注册器。提供显式安装、启停、能力清单和状态；项目内可执行插件需要用户明确启用，扩展的项目访问与工具审批由宿主控制。
- 选工具能力作为第一个外部调用样例，完成版本握手、能力级请求、取消和错误返回。打通后再把同一契约扩展到模型和上下文来源，随后按需求接入存储、执行或渠道能力。
- 提供可审阅的 MCP 能力清单、按项目启停和按需呈现工具。扩展管理页显示来源、版本、启用范围和加载失败原因。
- 发布可从仓库外使用的 SDK、示例和兼容说明。独立消费者覆盖公开承诺的能力，并在宿主更新时验证仍可加载和执行。

**验收场景**　在 JHarness 仓库之外构建一个示例工具插件，从打包桌面显式安装，在普通会话中调用并收到结果。验证禁用、API 版本不兼容、插件超时和进程退出时有清晰反馈，内置对话与工具仍可用。

## M6 · 可持续发布与升级

- 从干净 Windows 环境用声明的 JDK、锁定的 Node 依赖构建。先生成内置 Java，再用它跑端到端测试。验证的构建产物带版本、校验值和验证记录，并可在未安装系统 Java 的机器上启动。
- 验证从上一受支持版本升级，覆盖会话、项目记忆、收藏和设置。发布说明标明兼容范围、更新步骤和数据恢复方式。保留便携包，按实际分发方式决定安装器、签名和自动更新。
- 保留现有预算（JAR ≤ 24 MiB，解包目录 ≤ 450 MiB，后端协议响应 < 8 秒），并记录桌面冷启动至可用、长会话查询和任务恢复耗时。诊断信息包含版本、运行状态和可关联的任务 ID，避免采集凭据和原始项目内容。 [现有预算测试](../../tests/budgets/budget.test.cjs)
- 建立可复用的评测场景，覆盖真实项目的修改与验证、任务恢复后的副作用、长会话的检索质量和扩展故障。用同样的输入比较版本之间的完成情况、耗时和用量。

**验收场景**　从一个版本化提交生成 Windows 包，在干净环境跑一次完整桌面会话，并从上一受支持版本带数据升级。构建产物、校验值、兼容性结果和发布说明能互相对应。

## M7 · 多入口与可选集成

- 基于已有网关和 SDK 选择一个有实际用途的第二入口，例如 CLI 提交构建检查。复用桌面使用的会话、任务状态、工作区边界和审批规则。
- 按真实使用场景选择模型、渠道、存储或沙箱适配器。以可选扩展交付，每个适配器有独立的设置入口、兼容测试和维护范围，默认 Windows 包保持本地运行。

**验收场景**　从第二入口发起任务，在桌面看到同一个任务及其审批和结果。启用一个真实的可选适配器完成目标流程，停用后仍能使用默认的本地流程。

## M8 · 后台自动化与任务编排

- 让用户创建一次性、周期性和事件触发任务，选择项目、工作目录、输入模板、可用工具与结果接收位置。任务定义与每次运行分别编号，列表显示下一次触发、正在执行、上次结果和失败原因。
- 支持手动运行、暂停、恢复、取消和受控重试。触发重复到达时复用已有执行记录。沿用项目审批，等待决定的任务能把理由显示在桌面。
- 配置明确的依赖关系和失败处理，让小型工作流从一个任务的产物推进到下一个任务。需要跨项目调度时再接入看板视图、负责人分配和运行尝试历史。

**验收场景**　建立一个周期性构建检查和一个在构建成功后生成报告的后续任务。模拟一次重复触发、一次应用重启和一次构建失败，确认运行记录去重，失败能定位，重试的结果可查且关联原尝试。

## M9 · 多项目配置与运维

- 支持可命名的配置档案，维护项目目录、模型、Skill、扩展和任务默认值。支持按用途为主对话、评审、压缩等分配模型，并显示实际使用的模型、回退和用量。
- 让用户从管理界面查看活动任务、项目和数据状态、连通性、工具扩展与日志。支持备份和恢复工作区数据、会话、记忆与配置，在恢复或导入之前预览覆盖内容。
- 验证配置范围，确保项目之间的数据、权限和运行设置各自生效。为迁移、异常退出和配置失效提供可定位的诊断记录。

**验收场景**　建立两套配置档案并同时使用两个项目。验证模型、工具和会话检索分别遵守各自的范围。备份其中一个档案，用干净环境恢复，能重新打开对应会话和任务记录，并查看此前的运行结果。

## 近期交付顺序

1. **已交付 · 恢复入口可见。** 桌面可查询和清除中断记录。Windows 工作流已修复 JDK 17 的 `jlink` 参数，并在创建内置运行时之后执行 Node 测试。
2. **已交付 · 可续跑任务控制面。** 桌面已接入 `AgentSession`，持久任务可在重启后恢复、取消或继续；同会话支持排队后续任务和运行中补充指令，任务中心可跨会话定位。
3. **已交付 · 恢复、分叉、上下文与导出主链路。** 打包应用已从等待审批的任务恢复；未知工具结果可逐项核对；消息可创建带来源的干净分叉；上下文面板可检查最近请求并导出 Markdown/JSON；v1 迁移、长会话预算和中文/英文检索均有测试。剩余已批准执行中/结果未知的打包故障注入，以及 M3 迁移全集和召回质量语料。
